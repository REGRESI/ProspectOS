# Security boundaries

HTTP and worker startup both reject a database superuser, BYPASSRLS or ownership of any public application table. Production startup additionally requires verified Supabase configuration, Secure cookies and absence of the admin DSN. Only the separate migrator receives admin credentials. Runtime containers run as non-root users; the web process cannot mount private media.

Supabase access tokens are verified using asymmetric JWKS keys and exact issuer/audience/expiry/subject/role/confirmed-email checks. Tokens are exchanged for short opaque HttpOnly/SameSite=Lax sessions (Lax permits the authenticated top-level OAuth callback). Tokens and refresh credentials are not stored in browser storage. CSRF headers protect writes; signed webhook verification and user-bound, hashed, expiring single-use OAuth/invite capabilities protect their respective exceptions. Restored demo sessions cannot authenticate in Supabase mode or across issuers. Demo login and synthetic discovery are disabled in production. Signup, recovery, MFA and token refresh UI remain separate work.

Membership/roles are checked on each request and before worker dispatch. Tenant-owned business tables use FORCE RLS and transaction-local workspace context; composite foreign keys reject cross-workspace links. Authentication catalog/rate buckets, transient user-bound OAuth capabilities and the signed webhook event ledger have specialized server-only lookup patterns. Invitation lookup uses a narrow SECURITY DEFINER function with fixed search_path, no public execution and a capability hash; the app role never owns its table.

LinkedIn tokens are Fernet-encrypted with an injected key. Jobs store IDs and user content, not provider secrets. Publishing reloads actor membership, approval revision, media rights/alt text, actual granted scope, expiry, operator product approval and current policy. Dispatch timestamps enforce a UTC daily limit. Leases plus SKIP LOCKED claims prevent ordinary duplicate dispatch; uncertain outcomes become ambiguous and are not automatically resent. This does not promise exactly-once external delivery.

Private assets accept bounded valid PNG/JPEG/WebP only, reject SVG and pixel bombs, re-encode as JPEG without source metadata, and use server-issued storage keys. Original display names are basenames only. Every retrieval requires the correct authenticated tenant. Body limits apply before multipart parsing, including chunked requests. The shared local filesystem is not an S3 or malware-scanning implementation.

Structured request logs contain generated request IDs, matched route templates, method/status/duration, never raw query strings, invitation capabilities, OAuth codes or bodies. Uvicorn access logs are disabled. Audit/revision rows are append-only to the runtime role. Provider errors use safe stable codes. AI content stays an unverified suggestion; source IDs must belong to supplied evidence. Paid reservations cannot be reused through job retries.

Production release gates: independent security review, real provider approval/contract tests, HTTPS ingress, complete CSP, credential/backup rotation and restore tests, retention/DPA/legal review, distributed load/fairness and accessibility audits. A configured adapter is not evidence that live access or approval exists.
